# 1-显存计算	

​	大型语言模型（LLM）由于其巨大的参数规模，在普通的消费级硬件上直接运行通常是不切实际的。这类模型可能包含数十亿的参数，主要体现为权重，这不仅带来了高昂的存储成本，同时在进行推理时也需要大量的计算资源。为了有效处理这些模型，通常需要依赖拥有较大显存的图形处理单元（GPU）来加速推理。

​	我们以LLama-6B模型为例来估算模型大致需要的显存，首先考虑精度对所需要内存的影响：

| **序号** | **参数类型** | **bits（单个参数）** | **bytes（单个参数）** |
| -------- | ------------ | -------------------- | --------------------- |
| **1**    | fp32         | 32                   | 4                     |
| **2**    | fp16         | 16                   | 2                     |
| **3**    | int8         | 8                    | 1                     |

其次，考虑模型训练需要的内存（以1000为单位近似换算）如下表所示：

|                                  | **FP32**        | **Int8**        |              |
| -------------------------------- | --------------- | --------------- | ------------ |
| **模型内存****(以Llama-6B为例)** | **模型参数**    | 4bytes*6B=24G   | 1bytes*6B=6G |
| **模型梯度**                     | 4bytes*6B=24G   | 1bytes*6B=6G    |              |
| **优化器****(以Adam优化器为例)** | 2*4bytes*6B=48G | 2*1bytes*6B=12G |              |
| **cuda内核**                     | 约1.3G          |                 |              |
| **共计**                         | 约97.3G         | 约25.3G         |              |

​	再根据Llama的架构：计算中间变量内存，每个instance需要(4096+11008)*2048*32*1bytes=990MB的内存，所以一张A100（80 RAM）无法在FP32的精度下进行全参训练，却可以在int8的精度下，batch_size=50的设定下全参数训练。

  鉴于此，研究界正越来越多地探索缩小模型尺寸的方法，如优化训练技术或添加适配器组件等。量化（quantization）便是实现这一目标的关键技术之一，它有助于减少模型的大小和降低运算需求，从而使大型语言模型能够在资源更为有限的环境中部署和使用。
